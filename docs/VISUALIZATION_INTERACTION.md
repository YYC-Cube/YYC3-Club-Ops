# 可视化交互体系设计 · Visualization & Interaction

> YYC³ Club Ops · 前端设计系统 v1.0
>
> 目标：让**多店上下文、房间状态、经营数据**在同一套视觉语言中被快速理解与安全操作。

---

## 一、设计原则（对齐五维驱动）

| 维度 | 设计落点 |
|---|---|
| 时间 | 状态变化即时反馈；动效 ≤ 200ms；会话到期前静默续期 |
| 空间 | 门店 → 区域 → 包厢三级空间；页面信息按「当前门店」收敛 |
| 属性 | 颜色/形状/文案三通道编码，不依赖单一颜色 |
| 事件 | 每个操作都有 loading / success / error / empty 四态 |
| 关联 | 包厢 ↔ 订单 ↔ 门店 ↔ 会话的链路在 UI 中可追溯 |

**五高标准**：高可用（无数据也有可读空态）、高性能（首屏共享 103 kB）、高安全（危险操作二次确认）、高扩展（组件按域组合）、高智能（关键指标自动解释）。

## 二、设计令牌

### 2.1 颜色

| Token | 值 | 语义 | 使用场景 |
|---|---|---|---|
| `bg.canvas` | `slate-950` | 页面底色 | 全局 |
| `bg.surface` | `slate-900` | 卡片/弹窗 | 卡片、侧栏、表单 |
| `border.subtle` | `slate-800` | 分隔 | 卡片边框、表格线 |
| `text.primary` | `slate-100` | 主文本 | 标题、关键数字 |
| `text.secondary` | `slate-400` | 次文本 | 说明、单位 |
| `brand.primary` | `cyan-400` | 品牌/焦点 | 链接、焦点环 |
| `state.success` | `emerald-400` | 可用/通过 | 空闲包厢、成功 |
| `state.warning` | `amber-400` | 预览/待处理 | Mock、维修、待清洁 |
| `state.danger` | `rose-400` | 故障/禁止 | 越权、失败、占用冲突 |

> 颜色必须与图标/文案组合使用；禁止仅靠红绿区分状态。

### 2.2 字号与间距

| 层级 | 规格 | 用途 |
|---|---|---|
| 页面标题 | 20–24px / semibold | 页面名、门店名 |
| 区块标题 | 16px / medium | 卡片标题 |
| 正文 | 14px | 表单、列表 |
| 辅助 | 12px | 说明、时间 |
| 微标签 | 9–10px | 状态徽标、侧栏提示 |
| 间距 | 4 的倍数（4/8/12/16/24） | 统一节奏 |
| 圆角 | 6–8px | 卡片/按钮；对话框 12px |

### 2.3 动效

| 场景 | 时长 | 缓动 |
|---|---|---|
| 按钮/状态切换 | 120ms | ease-out |
| 对话框/弹窗 | 180–200ms | ease-out |
| 骨架/加载 | 1.2s loop | linear |
| 页面切换 | ≤ 200ms | ease-in-out |

- 支持 `prefers-reduced-motion`，关闭非必要位移；
- 不使用弹跳/旋转等与业务无关的动效；
- 状态变化优先“就地更新”，避免整页闪烁。

## 三、信息架构

```text
AppLayout
├── 侧栏：门店切换器（租户 → 当前门店 → 授权门店）
├── 分组：POS（包厢/点单） | 管理（看板/报表/会员/库存/员工/设置）
└── 主区：页面标题（当前门店）→ 内容 → 反馈层（错误/空态）
```

- 管理端与 POS 端按路由自动切换分组；
- 所有页面必须显示**当前门店**，禁止隐式使用“默认门店”；
- 会话错误在侧栏常驻可重试，不静默回退。

## 四、核心组件交互规范

### 4.1 包厢卡片（Room Card）

| 状态 | 视觉 | 可执行动作 |
|---|---|---|
| `available` | 绿色边框 + 空闲 | 开房、维修 |
| `occupied` | 琥珀边框 + 计时 | 点单、结账 |
| `cleaning` | 蓝色边框 + 待清洁 | 清台 |
| `maintenance` | 灰色边框 + 维修 | 恢复 |
| `reserved` | 紫色边框 + 预定 | 开房/取消（规划） |

- 卡片必须可键盘聚焦（`button`），带 `aria-label`（含包厢名与状态）；
- 点击打开详情对话框；动作后按 `roomId` 派生最新状态，不使用快照；
- 空列表展示空态与“刷新”入口，不展示假数据。

### 4.2 详情对话框（Room Detail）

- `role="dialog"`、`aria-modal="true"`、Esc 关闭、焦点进入并返回触发元素；
- 危险动作（结账/维修）需显示当前状态与影响；
- 金额统一“分 → 元”展示，保留两位小数；
- 结账展示 `billableHours` 与 `totalCents`，并说明进位规则。

### 4.3 门店切换器（Store Switcher）

- 只展示会话授权门店；
- 未授权/切换失败：保留原门店并展示错误，禁止回退；
- Mock 模式显示 `Mock` 徽标，避免误认为真实数据；
- 退出登录需清理本地上下文并跳转 `/login`。

### 4.4 登录与会话

- 登录失败按服务端 `code` 展示：`rate_limited` 显示 `Retry-After`；
- CSRF 失败（403）提示“刷新页面后重试”，不自动重放写操作；
- 会话续期失败进入 error 态，引导重新登录；
- 表单错误使用 `role="alert"`，不遮挡输入。

## 五、数据可视化规范

### 5.1 图表选择

| 场景 | 图表 | 要求 |
|---|---|---|
| 营收趋势 | 折线/面积 | 标注单位、时间范围、数据更新时间 |
| 品类占比 | 环形/条形 | ≤ 6 类，其余归“其他” |
| 包厢利用率 | 横向条形 | 同时显示分子/分母 |
| 员工/会员排行 | 表格 | 支持排序与分页 |
| 实时状态 | 状态卡片 | 颜色 + 文案 + 图标 |

### 5.2 数据状态四态

| 状态 | 表现 |
|---|---|
| loading | 骨架屏，不显示 0 |
| empty | 空态插画/文案 + 下一步动作 |
| error | 错误文案 + 重试；保留上次成功数据并标注时间 |
| ready | 数据 + 更新时间 |

> 禁止“失败静默返回 Mock”；禁止把空数据渲染为 0 或假趋势。

### 5.3 金额与时间

- 金额以“分”为唯一存储单位，展示时转元；
- 时长按分钟展示，计费按“15 分钟进位、最低 1 小时”；
- 时间统一 `Asia/Shanghai`，跨日营业口径待 Phase 3 定义。

## 六、响应式与无障碍

| 项 | 标准 |
|---|---|
| 断点 | 390 / 768 / 1024 / 1440 |
| 移动端 | 侧栏收窄为图标栏；390px 无横向滚动 |
| 对比度 | 正文 ≥ 4.5:1；大字号 ≥ 3:1 |
| 焦点 | 所有交互元素可见 focus ring（cyan-400） |
| 键盘 | Tab 顺序符合阅读顺序；对话框焦点闭环 |
| 语义 | 状态使用 `aria-live` 提示；错误 `role="alert"` |
| 触控 | 可点击区域 ≥ 40×40（移动端） |

## 七、反模式清单

- ❌ 只靠颜色表达状态（红/绿）
- ❌ 卡片点击后整页刷新丢失上下文
- ❌ 弹窗内再叠弹窗
- ❌ 失败后静默展示 Mock 数据
- ❌ 未标注单位的金额/比例
- ❌ 超过 200ms 的装饰性动效
- ❌ 在 POS 关键路径加入非必要确认弹窗
