# 🎭 艺人设置配置规范（PC 端 7 项）

> **来源**：用户提供的 7 张 PC 端截图（2026-10-31）。
> **端侧分工**：PC 端（CMS）负责配置；App（智慧商家.app）负责艺人档案/报备/上下钟/台费/台票的**管理编辑**，并按配置生效；数据回传 CMS。
> **配置粒度**：**门店级**（每个门店一套）。
> **选项类型**：以“是/否”或“开启/关闭”为主；「签到后多久可签退」为**数字（分钟）**；「上钟模式」为**台费 / 台票 / 自定义**三选一。

---

## 0. 总览

| # | 配置项 | 子项数 | 选项类型 | 影响端 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 艺人资料必填项设置 | 2 | 是/否 | App 新增/审核艺人资料 | 身份证、等级是否必填 |
| 2 | 艺人报备设置 | 4 | 开启/关闭 | App / 微信端报备入口 | 微信、扫码、刷卡、二次签到 |
| 3 | 艺人签到后多久可签退 | 1 | 数字（分钟） | App 签退 | 0 表示签到后可立即签退 |
| 4 | 艺人是否支持手动扫码下钟 | 1 | 是/否 | App 下钟 | 否 = 需下钟审批/服务停止/关房后自动下钟 |
| 5 | 未签到是否支持上钟打卡 | 1 | 是/否 | App 包厢扫码上钟 | 否 = 未报备签到无法扫码上钟 |
| 6 | 台票购买设置 | 3 | 是/否 | App 台票购买 | 未签到、购票未使用、上钟状态下是否可购买 |
| 7 | 艺人上钟模式设置 | 1 | 台费/台票/自定义 | App 上钟 | 台费扣费；台票需先购票；自定义待定义 |

> 截图中的门店示例为某门店；配置必须按 `storeId` 隔离，不可跨店复用。

## 1. 逐项配置说明

### 1.1 艺人资料必填项设置

| 子项 | 选项 | 默认/截图值 | 生效规则 |
| --- | --- | --- | --- |
| 艺人身份证是否必填 | 是 / 否 | 否 | **默认是必填**；选“否”后 App 新增/审核艺人资料可不填身份证 |
| 艺人资料等级是否必填 | 是 / 否 | 否 | 选“是”后，App 新增艺人资料或审核艺人资料时**必须选择艺人等级** |

**截图说明原文**
1. 艺人身份证号默认是必填，如不想必填选择否。
2. 艺人等级是否必填，【是】则 App 端新增艺人资料或审核艺人资料时，必须选择艺人等级。

**校验要求**
- 身份证选“是”时，App 提交资料必须通过身份证格式校验；选“否”时允许为空，但填写后仍需格式校验。
- 等级选“是”时，`levelId` 必填；选“否”时可为空。
- 审核流程与新增流程使用同一校验规则，避免“新增可空、审核必填”的不一致。

### 1.2 艺人报备设置（4 个开关）

| 子项 | 选项 | 截图值 | 关闭后的效果 |
| --- | --- | --- | --- |
| 艺人微信报备设置 | 开启 / 关闭 | 开启 | 关闭后，**巨嗨佳人微信端报备入口隐藏** |
| 艺人 App 端扫码报备设置 | 开启 / 关闭 | 开启 | 关闭后，App 端艺人报备二维码不显示 |
| 艺人 App 端刷卡报备设置 | 开启 / 关闭 | 开启 | 关闭后，App 端不支持刷卡报备 |
| 二次签到设置 | 开启 / 关闭 | 关闭 | 开启后，艺人报备签到当天支持**签退后再次签到** |

**截图说明原文**
1. 艺人微信报备，设置关闭后，巨嗨佳人微信端报备入口隐藏。
2. 艺人 App 端扫码报备设置，关闭后 App 端艺人报备二维码不显示。
3. 艺人 App 端刷卡报备设置，关闭后 App 端不支持刷卡报备。
4. 二次签到设置：设置开启后，艺人报备签到当天可支持签退后再次签到。

**校验要求**
- 四个开关互相独立，但至少保留一种报备方式（若全部关闭，需提示“该门店无可用报备入口”）。
- 二次签到开启时，需允许同一营业日内“签到→签退→再次签到”，并记录多次签到区间。
- 报备开关只影响入口展示与提交，不删除历史报备记录。

### 1.3 艺人签到后多久可签退

| 项 | 选项 | 截图值 | 说明 |
| --- | --- | --- | --- |
| 可签退间隔 | 数字（分钟） | 0 | 0 = 签到后可立即签退；>0 = 需等待 N 分钟后才允许签退 |

**校验要求**
- 非负整数；建议上限（如 0–1440 分钟）待产品确认。
- App 签退时按“当前时间 - 最近一次签到时间”判断；二次签到场景按**最近一次签到**计算。
- CMS 报表中的签退时间以 App 实际提交时间为准，不因配置回算。

### 1.4 艺人是否支持手动扫码下钟

| 选项 | 截图值 | 规则 |
| --- | --- | --- |
| 是 | 是 | 艺人默认支持在 App 手动扫码下钟 |
| 否 | — | 艺人需发起**下钟审批**；审批通过、服务停止或关房后，才能自动下钟 |

**截图说明原文**：艺人默认支持扫码下钟，若选否则艺人需发起下钟审批，审批通过、服务停止或关房后才能自动下钟。

**校验要求**
- 选“否”时必须存在审批流（审批人/门店主管）；无审批人时不允许保存或给出告警。
- “服务停止/关房”事件需触发自动下钟，且写入上下钟记录的操作来源（手动/审批/自动）。

### 1.5 未签到是否支持上钟打卡

| 选项 | 截图值 | 规则 |
| --- | --- | --- |
| 是 | 是 | 未报备签到时，仍可在包厢扫码上钟 |
| 否 | — | 未报备签到时，**在包厢无法扫码上钟** |

**截图说明原文**：否：艺人未报备签到时，在包厢无法扫码上钟。

**校验要求**
- 选“否”时，上钟接口必须校验当天报备签到状态；未签到返回明确错误码（如 `ARTIST_NOT_CHECKED_IN`）。
- 补报备后允许立即上钟；补报备与上钟的时间顺序需可追溯。

### 1.6 台票购买设置（3 个子项）

| 子项 | 选项 | 截图值 | 选“否”后的规则 |
| --- | --- | --- | --- |
| 未签到是否可购买 | 是 / 否 | 否 | 艺人未报备签到时，无法购买台票 |
| 购票未使用是否可购买 | 是 / 否 | 否 | 艺人购买台票后，同一营业日内未上钟使用，**无法重复购票** |
| 上钟状态下是否可购买 | 是 / 否 | 否 | 艺人当前处于上钟状态未下钟的，无法购买台票 |

**截图说明原文**
1. 未签到是否可购买，否：艺人未报备签到时，无法购买台票。
2. 购票未使用是否可购买，否：艺人购买台票后，单个营业日内未上钟使用的，无法重复购票。
3. 上钟状态下是否可购买，否：艺人当前处于上钟状态未下钟的，无法购买台票。

**校验要求**
- “同一营业日”按门店营业日（08:00–08:00）计算；跨零点需归属到正确营业日。
- 台票状态机至少包含：已购买、未使用、已使用、作废；重复购买校验以“未使用”票为准。
- 上钟状态下购买校验需读取实时上下钟状态，避免并发重复购票（数据库唯一约束/幂等键）。

### 1.7 艺人上钟模式设置

| 选项 | 截图值 | 规则 |
| --- | --- | --- |
| 台费 | 是（当前） | App 端设置台费规则后，艺人上钟时**扣取对应台费规则金额** |
| 台票 | — | 艺人上钟时判断是否购买台票，**需购买台票后方可正常上钟** |
| 自定义 | — | 截图未给出说明，需产品定义自定义规则（如按时长/按台费+台票组合/按等级） |

**截图说明原文**
1. 台费模式：App 端设置有台费规则时，艺人上钟扣取对应台费规则金额。
2. 台票模式：艺人上钟时判断是否购买台票，需购买台票后方可正常上钟。

**校验要求**
- 台费模式：上钟时必须能解析到该门店/等级/时段对应的台费规则；无规则时应阻止上钟或提示配置缺失。
- 台票模式：上钟前校验“当日已购且未使用”的台票；无票时返回明确错误码（如 `ARTIST_TICKET_REQUIRED`）。
- 自定义模式：在规则未定义前，**不允许保存/上线**；需补充自定义规则说明与验收用例。

## 2. 配置生效链路

```
PC（CMS）艺人设置
   │ 保存（门店级）
   ▼
配置表 artist_setting（storeId 唯一）
   │ 读取/缓存
   ▼
App（智慧商家.app）
   ├─ 新增/审核艺人资料：身份证/等级必填校验
   ├─ 报备：微信/扫码/刷卡入口 + 二次签到
   ├─ 签退：签到后 N 分钟校验
   ├─ 下钟：手动扫码 或 审批/服务停止/关房自动
   ├─ 上钟：未签到是否允许；台费/台票/自定义校验
   └─ 台票购买：未签到/未使用/上钟中三类拦截
   │
   ▼
业务数据回传 CMS（档案/报备/上下钟/台费/台票）
   │
   ▼
CMS 只读查询 + 报表 + 导出
```

**生效时机**：保存后即时生效（App 下次请求读取最新配置）；建议加 60s 缓存 + 保存后主动失效。
**冲突处理**：App 本地缓存版本号与 CMS 配置版本号不一致时，以 CMS 最新版本为准并提示刷新。

## 3. 数据模型建议

```sql
-- 门店级艺人设置（示意）
artist_setting (
  store_id                    varchar primary key,
  id_card_required            boolean not null default true,   -- 身份证是否必填
  level_required              boolean not null default false,  -- 等级是否必填
  wechat_report_enabled       boolean not null default true,   -- 微信报备
  qr_report_enabled           boolean not null default true,   -- App 扫码报备
  card_report_enabled         boolean not null default true,   -- App 刷卡报备
  second_checkin_enabled      boolean not null default false,  -- 二次签到
  checkin_to_checkout_minutes integer not null default 0,      -- 签退间隔（分钟）
  manual_clockout_enabled     boolean not null default true,   -- 手动扫码下钟
  clockin_without_checkin     boolean not null default true,   -- 未签到可上钟
  ticket_buy_without_checkin  boolean not null default false,  -- 未签到可购票
  ticket_buy_when_unused      boolean not null default false,  -- 未使用可重复购票
  ticket_buy_on_duty          boolean not null default false,  -- 上钟中可购票
  clock_mode                  varchar not null default 'fee',  -- fee|ticket|custom
  custom_rule_json            jsonb,                            -- 自定义模式规则（待定义）
  version                     integer not null default 1,
  updated_by                  varchar,
  updated_at                  timestamptz not null default now()
)
```

**约束**
- `store_id` 主键/唯一，禁止跨店共享。
- `clock_mode='custom'` 时 `custom_rule_json` 必填（待规则定义后启用）。
- 所有修改写 `artist_setting_audit`（操作人、旧值、新值、时间、门店）。

## 4. API 建议

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/artist/settings?storeId=...` | 读取门店配置（App 与 CMS 共用） |
| PUT | `/api/artist/settings` | 保存配置（仅授权角色；写审计） |
| GET | `/api/artist/settings/audit` | 配置变更审计（CMS 只读） |
| GET | `/api/artist/settings/effective?storeId=&artistId=` | App 获取生效配置（含版本号） |

**权限**：仅店长/超级管理员可写；普通员工只读或不可见。
**幂等**：PUT 携带 `version`，版本冲突返回 409。
**审计**：每次保存记录变更前后差异，便于追责。

## 5. 配置影响矩阵

| 配置 | 影响 App 行为 | 影响 CMS 报表/查询 |
| --- | --- | --- |
| 身份证/等级必填 | 新增/审核资料校验 | 艺人档案完整率 |
| 报备开关 | 微信/扫码/刷卡入口 | 报备明细/汇总 |
| 二次签到 | 同日多次签到 | 报备次数/在岗时长 |
| 签退间隔 | 签退时间限制 | 上下钟时长、台费计算 |
| 手动扫码下钟 | 下钟方式/审批 | 下钟来源、审批记录 |
| 未签到可上钟 | 上钟前置校验 | 未报备上钟异常 |
| 台票购买三项 | 购票拦截 | 台票购买/使用报表 |
| 上钟模式 | 台费扣费/台票校验 | 台费流水、台票核销 |

## 6. 验收清单

- [ ] 7 项配置均按 `storeId` 隔离，切店后读取正确
- [ ] 身份证/等级必填在“新增”和“审核”两条链路一致
- [ ] 4 个报备开关独立生效；全部关闭时有告警
- [ ] 签退间隔 0/N 分钟用例通过（含二次签到）
- [ ] 手动下钟关闭时，审批/服务停止/关房三种路径均可下钟
- [ ] 未签到禁止上钟时返回明确错误码
- [ ] 台票三项拦截用例通过（未签到/未使用/上钟中）
- [ ] 上钟模式三选一；自定义未定义时禁止保存/上线
- [ ] 配置修改写审计（旧值/新值/操作人/时间）
- [ ] App 与 CMS 配置版本一致；冲突有提示
