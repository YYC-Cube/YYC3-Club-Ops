## 关键决策记录

| 决策 | 背景 | 选择 | 原因 |
| --- | --- | --- | --- |
| 定位多店 SaaS | 负责人确认 | 租户 + 门店两级模型 | 平台化与数据隔离 |
| Phase 1 不接半成品后端 | 无契约、无后端归属 | 本地状态机 + 显式 Mock + 预览标识 | 避免制造新的假实现 |
| 门禁全开 | 历史关闭类型/lint | CI + 构建双重校验 | 防止缺陷直达 main |
| 结账后进入待清洁 | 原实现直接回空闲 | `occupied → cleaning → available` | 符合 KTV 实际运营 |
| 金额统一分单位 | 浮点风险 | `lib/money.ts` + 单测 | 资金安全 |
| 先接线后重写 | 13,869 行不可达 | Phase 2 评估复用/归档 | 保护既有投入 |
| 存储选 PostgreSQL + RLS | 多店隔离需数据库层兜底 | `app` schema + 三张强制 RLS 业务表 + app 角色 | 应用漏洞不越权，作用域显式化 |
| 仓储端口化 | 测试需无库可跑 | `AppRepository` + `MemoryRepository` / `PostgresRepository` | 单测与 CI 不依赖数据库 |
| 认证表 RLS 采用 definer 登录函数 | 登录前无租户上下文 | `auth_lookup` 精确 1 行 + `app_user/user_store` 不 FORCE | 避免登录前放开整表读取 |
| 登录限流落库 | 多实例/重启需一致 | `login_throttle` + 原子 UPSERT 函数 | 不依赖单机内存 |
| CSRF 用同步令牌而非双提交 Cookie | 需要会话绑定、可服务端校验 | session 存 `csrf_token` + `X-CSRF-Token` | 避免子域/双提交弱点 |
| 会话绝对上限 | 防止无限续期 | `created_at + SESSION_MAX_LIFETIME_SECONDS` | 安全与体验平衡 |

## 遇到的问题与解决方案

| 问题 | 解决方案 | 经验 |
| --- | --- | --- |
| pnpm 12 不再读取 `package.json.pnpm` | 迁移到 `pnpm-workspace.yaml`，用 `allowBuilds` | 版本升级需同步配置位置 |
| pnpm 12 默认冻结锁文件导致新依赖被拒 | `pnpm install --lockfile-only` 后重装 | CI 与本地命令要区分 |
| 390px 出现 394px 横向溢出 | 侧栏移动端收窄 + 文本响应式隐藏 | E2E 能发现真实回归 |
| 覆盖率阈值未达标 | 补 order store 测试 | 阈值应覆盖真实域 |
| Next 推断父目录 `bun.lock` 为根 | `outputFileTracingRoot` | 多项目目录需显式根 |
| seed 触发 RLS 拒绝写入 | 事务内先 `set_config` 再插 `room` | FORCE RLS 对 owner 同样生效 |
| app 角色登录 500（42501） | `session` 补 `GRANT SELECT` | `DELETE ... WHERE` 与查询都需要 SELECT |
| PG 集成测试重置失效 | `beforeEach` 显式 `BEGIN/COMMIT` | 事务级 `set_config` 需真实事务 |
| 登录前查询被 FORCE RLS 挡住 | `app_user/user_store` 仅 ENABLE + definer 函数 | FORCE 会连 owner 一起限制 |
| 成功登录被限流拦截 | 限流在密码校验前计数；用例改为先失败再成功 | 阈值语义是“尝试次数”而非“失败次数” |
| 刷新 SQL 参数类型推断失败 | WHERE 显式引用 `tenant_id/user_id` | 未使用的 `$n` 必须参与条件或删除 |
| 文件替换误删 describe 头 | 重读测试文件并补回分组 | 大段替换后必须立即 typecheck/test |
