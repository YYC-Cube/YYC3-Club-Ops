# 🔍 登录/会话审计与管理员强制下线

## 1. 本次范围

承接 `12-CSRF与会话刷新` 的「已知边界」，落地会话治理能力：

- **审计**：登录成功/失败、登出、续期、强制下线全埋点，租户作用域查询；
- **强制下线**：`manager/admin` 可撤销目标用户在租户内的全部有效会话；
- 契约（OpenAPI）、前端路径事实源、API/数据库/安全文档同步。

## 2. 数据库（004_auth_audit.sql）

| 对象 | 说明 |
|---|---|
| 表 `app.auth_audit` | 追加写审计；`id bigserial`、`tenant_id`（登录前可空）、`user_id`、`actor_id`、`phone`、`event`、`ip`、`user_agent`、`created_at` |
| 约束 | `event` 限定 5 类：`login_success` / `login_failure` / `logout` / `session_refresh` / `force_logout` |
| 索引 | `(tenant_id, created_at DESC)`、`(user_id, created_at DESC)` |
| RLS | `ENABLE + FORCE`；SELECT 按 `app.tenant_id`；INSERT 用 `tenant_id IS NOT DISTINCT FROM NULLIF(current_setting(...),'')`，同时放行「登录前空租户」与「本人租户」，拒绝跨租户；**无 UPDATE/DELETE 策略 → 历史不可篡改** |
| 权限 | 应用角色仅 `SELECT, INSERT` + 序列 `USAGE, SELECT` |
| 函数 `app.revoke_user_sessions(actor, tenant, user)` | `SECURITY DEFINER`；先校验 actor 为 `manager/admin`（纵深防御），再在事务内切换 `app.user_id` 为目标用户撤销会话，返回数量 |

> `session` 为 FORCE RLS，管理员事务作用域只覆盖本人会话，因此批量撤销必须走这个 definer 函数，而不是直接 `UPDATE app.session`。

## 3. 服务端实现

### 3.1 审计埋点（`server/app.ts`）

| 事件 | 触发点 | 关键字段 |
|---|---|---|
| `login_failure` | 账号不存在或密码错误 | `phone`；手机号不存在时 `tenant_id=null` |
| `login_success` | 会话创建成功后 | `tenant_id`、`user_id`、`actor_id`、`phone`、`ip`、`ua` |
| `session_refresh` | `POST /auth/refresh` 成功后 | 当前会话身份 |
| `logout` | 会话已撤销 | 当前会话身份 |
| `force_logout` | 管理端强制下线成功后 | `actor_id`=管理员，`user_id`=被下线者 |

**审计失败不阻断主流程**：`safeAudit()` 包裹写库调用，异常只写服务端日志（登录可用性优先）。

### 3.2 端点

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/admin/auth-audit?limit=` | `manager/admin` | 本租户审计，倒序；`limit` 1–200，默认 50，越界 400 |
| POST | `/api/admin/users/{userId}/force-logout` | `manager/admin` + CSRF | 撤销目标用户全部会话，返回 `revokedSessions` |

校验顺序：`requireAuth`（Cookie → 会话 → 用户 → 租户 → 门店 → CSRF）→ 角色（`403 forbidden_role`）→ 目标用户存在性（同租户，`404 not_found`）→ DB 函数再校验 → 审计。

### 3.3 仓储端口（Memory / Postgres 对齐）

| 方法 | 实现要点 |
|---|---|
| `recordAuthAudit` | Postgres 走 `withScope`（空租户写空串，策略侧 NULLIF → NULL） |
| `listAuthAudit` | Postgres 按 `tenant_id` 过滤 + 倒序 + LIMIT；Memory 用租户过滤 + 序号倒序 |
| `revokeUserSessions` | Postgres 调 `app.revoke_user_sessions`；Memory 复刻 DB 角色校验与撤销语义 |

### 5.2 真实 API 实测（3032 + PostgreSQL）

```text
login cashier/manager = 200（各自拿到 csrfToken）
cashier GET /auth/session = 200
POST /admin/users/{cashier}/force-logout（无 CSRF）= 403 csrf_invalid
POST force-logout（cashier 操作）= 403 forbidden_role
POST force-logout（manager 操作）= 200 {"revokedSessions":1}
cashier 旧 Cookie GET /auth/session = 401 unauthorized
manager 自身 GET /auth/session = 200（不受影响）
GET /admin/auth-audit（manager）= 200，倒序含 force_logout(manager→cashier)
空租户审计行可见数 = 0（租户作用域隔离）
POST /auth/refresh = 200；被下线 cashier 重新登录 = 200；manager logout = 200
```

### 5.4 顺带修复

`verifySessionToken` 原先用真实墙钟校验 `exp`，与 `createApp({ now })` 注入的时钟不一致，导致固定时钟测试用例在真实时间推进后集体 401（定时炸弹）。现签名不变、增加可选 `nowMs` 参数，`app.ts` 统一传入 `now().getTime()`，测试与运行时行为一致。
