# 🤝 项目对接与协作指引

## 1. 关键对接人及沟通事项

> **定位已确认**：多店 SaaS（ADR-001）。仓库内**没有责任人清单**（仅见提交者 `YYC-Cube`），以下角色按职责给出对接事项与确认路径。标 ❓ 的需业务方补齐。

| 角色 | 当前识别 | 需对接事项 | 确认路径 |
| --- | --- | --- | --- |
| 产品/业务负责人 | ❓ 待确认 | 产品定位、范围边界、8 模块优先级、验收口径、“演示版”标识 | 组织管理员/项目发起人 |
| 技术负责人 / 主维护者 | `YYC-Cube`（提交者） | 架构决策、技术选型、PR 合并、发布权限 | `git log` / GitHub 组织 Owner |
| 前端开发 | ❓ 待确认 | 路由接线、POS/房间闭环、组件复用决策 | 仓库 Contributors |
| 后端/数据负责人 | ❓ 待确认（本地库已由本会话建好） | API 契约、数据库变更评审、支付回调、事务与幂等、备份恢复 | 需索取后端仓库/OpenAPI；DB 见 §7 |

## 2. 信息同步机制与频次

| 机制 | 频次 | 参与人 | 产出 | 载体 |
| --- | --- | --- | --- | --- |
| 每日站会（异步） | 每工作日 | 开发/测试 | 昨日/今日/阻塞 | Issue 评论或群消息 |
| 周度技术同步 | 每周 1 次（30 min） | 技术/产品/测试 | 决策、风险、排期变更 | 会议纪要 + 仓库文档 |
| 里程碑评审 | M1~M4 各 1 次 | 全体 | 验收结论/放行决定 | `docs/{会话}/` 更新 |
| 安全与依赖巡检 | 每两周 | 技术/运维 | audit 结果与升级 PR | CI + Issue |
| 文档同步 | 每次会话结束 | AI 导师/开发 | 00~05 文档更新 | `docs/{项目}-{导师}-{日期}/` |
| 线上状态巡检 | 每周 | 运维 | 可用性/错误率/回滚记录 | 监控看板（待建） |

**同步原则**：所有“已完成”必须有命令结果、截图或线上验证；文档只描述“实现态”，计划态单独标注。

## 3. 跨团队协作流程与卡点

### 3.1 建议的标准流程

```
Issue（含验收标准）
   ↓
分支 feat|fix/<主题>（从 main）
   ↓
本地自测：pnpm exec tsc --noEmit / pnpm lint / pnpm test / pnpm build
   ↓
PR（模板：变更说明 + 验证证据 + 风险 + 回滚）
   ↓
CI 门禁：install(frozen) → typecheck → lint → test → audit → build
   ↓
评审（至少 1 名；安全/支付变更需 2 名）
   ↓
合并 main → 自动部署 Pages → 线上冒烟 → 记录发布
```

### 3.2 当前流程卡点（按严重度）

| 卡点 | 现状 | 影响 | 优化建议 |
| --- | --- | --- | --- |
| 无质量门禁 | CI 仅 install/build/deploy | 缺陷直达线上 | 增加 typecheck/lint/test/audit 步骤 |
| 无测试资产 | 0 用例，`pnpm test` 不存在 | 无法回归 | 先建 Vitest + Playwright 骨架 |
| 无 lockfile | 安装不可复现 | 版本漂移/漏洞不可控 | 提交 lockfile + frozen 安装 |
| 无责任人 | 角色空缺 | 决策慢、交接断裂 | 补齐 RACI 并写入 `docs/OWNERS.md` |
| 无后端契约 | `apiClient` 孤岛、Mock 降级 | 前后端无法联调 | 契约先行（OpenAPI），Mock 由契约生成 |
| 文档与实现不符 | 仓库地址/版本/CI/persist 描述错误 | 误导新人 | 文档加“实现态/计划态”标记 |
| 线上无监控 | 无错误上报/审计 | 排障靠猜 | 接入错误上报与关键操作日志 |
| 单维护者风险 | 仅 1 名提交者 | 关键路径不可用 | 至少 2 人具备合并/发布权限 |
| 发布无版本 | 无 Tag/CHANGELOG | 无法回滚定位 | 语义化版本 + Release Notes |
| 部署目标限制 | GitHub Pages 无服务端/自定义头 | 无法承载 POS | 若转生产，迁移到支持 SSR/头的平台 |

### 3.3 PR 模板建议（可直接落地）

```markdown
## 变更说明
<!-- 做了什么、为什么 -->

## 关联 Issue
Closes #

## 验证证据
- [ ] `pnpm exec tsc --noEmit`
- [ ] `pnpm lint`
- [ ] `pnpm test`
- [ ] `pnpm build`
- [ ] 路由/交互截图或录屏

## 风险与回滚
<!-- 影响范围、数据/资金风险、回滚方式 -->

## 检查项
- [ ] 未硬编码密钥
- [ ] 金额/权限/幂等已验证（如适用）
- [ ] 文档已同步
```

## 4. 需求变更与问题上报路径

### 4.1 需求变更

| 变更级别 | 示例 | 流程 | 审批 |
| --- | --- | --- | --- |
| L1 小改动 | 文案、样式、排序 | Issue → PR → 1 人评审 | 前端负责人 |
| L2 功能调整 | 新增字段、交互变化 | 需求说明 → 技术评估 → 排期 → PR | 产品 + 技术负责人 |
| L3 范围/架构变更 | 新增模块、接支付、换部署形态 | 变更单（影响/成本/风险）→ 评审会 → 里程碑调整 | 业务负责人 + 技术负责人 |
| L4 紧急修复 | 线上不可用、资金/数据事故 | 热修分支 → 双人复核 → 部署 → 复盘 | 技术负责人（事后补单） |

> 变更必须回答三件事：**影响哪些模块、是否影响资金/权限、如何回滚**。

### 4.2 问题上报

| 问题类型 | 渠道 | 时限 |
| --- | --- | --- |
| 普通缺陷 | GitHub Issue（附复现步骤/截图/环境） | 24h 内分级 |
| P0 线上故障（不可收银/账务异常） | 即时通讯 + Issue（标 `P0`） | 15 分钟内响应，2 小时内给缓解 |
| 安全漏洞 | **不要公开 Issue**，邮件 `admin@0379.email`，主题 `[SECURITY] YYC3-Club-Ops` | 按 `SECURITY.md`：48h 确认 / 7 天分级 / 高危 30 天修复 |
| 依赖漏洞 | Dependabot PR + `pnpm audit` | 高危 7 天内合并 |
| 文档错误 | `docs/<主题>` 分支 PR | 随迭代修复 |

### 4.3 Issue 必填字段

- 环境（本地/线上、浏览器、账号角色）
- 复现步骤（最少步骤）
- 期望 vs 实际
- 证据（截图/录屏/控制台/请求 ID）
- 影响（是否涉及金额、订单、权限、库存）
- 优先级建议（P0~P3）

## 6. 给业务方的三句话

1. **现在能演示，不能营业**：线上 6 个管理模块仍是“开发中”，收银台没有收银能力。
2. **最大的浪费不是没做，而是做了没接上**：约 94% 的代码未进入任何路由，需要一次“接线/归档”决策。
3. **最快的止损是 5 件事**：加演示标识、提交 lockfile、升级 Next、打开质量门禁、接通房间动作。约 1 周即可显著降低风险。

## 7. 数据库与安全协作补充（Phase 2）

> 适用于新增数据库变更、跨店隔离与上线安全评审。

### 7.1 数据库变更流程

| 步骤 | 要求 |
| --- | --- |
| 1. 迁移文件 | 只允许新增 `db/migrations/NNN_*.sql`；禁止修改已应用的历史迁移 |
| 2. 本地执行 | `pnpm db:migrate` + `pnpm db:seed`（owner 角色） |
| 3. 测试库 | `pnpm db:migrate:test` + `pnpm db:seed:test`，再跑 `pnpm test` |
| 4. 权限 | 新表必须显式 `GRANT` 给 `yyc3_club_ops_app`；RLS 表需 `FORCE` |
| 5. 评审 | 涉及 RLS/权限/金额/唯一约束的变更需 2 人评审 |
| 6. 发布 | 先迁移后发应用；回滚以“兼容旧版本”为目标，不做破坏性 DROP |

### 7.2 安全事项对接

| 事项 | 负责角色 | 说明 |
| --- | --- | --- |
| `pg_hba` 收紧（trust → scram-sha-256） | 数据负责人 | 共享网络或上线前必须执行 |
| auth 表 RLS / 登录函数 | 后端 | ✅ 已完成（`002_auth_rls.sql`） |
| 登录限流 | 后端 | ✅ 已完成（落库，429 + `Retry-After`） |
| CSRF / 会话刷新 | 后端 | ✅ 已完成（同步令牌 + `/auth/refresh`） |
| 登录/会话审计、强制下线 | 后端 | 上线前 P1 |
| 备份/PITR 演练、监控 | 运维 | 生产准入项 |
| 凭据管理 | 全体 | 仅 `.env.local`（gitignored），文档与 PR 不出现真实密码 |

### 7.3 交接必读

- 数据库拓扑与角色：`10-PostgreSQL适用性分析.md`
- 落地验证证据：`04-测试验证方案与执行结果.md` §12/§13/§14
- 认证 RLS 与登录限流：`11-认证RLS与登录限流.md`
- CSRF 与会话刷新：`12-CSRF与会话刷新.md`
- 运行命令：`pnpm api:dev`（3032）、`pnpm db:migrate`、`pnpm db:seed`
