# 📋 任务规划与节点目标

## 规划总则

> **执行有规划，规划有节点，节点有目标，目标可评估**

**定位（已确认）**：多店 KTV 运营 SaaS —— 一套平台服务多个商户/门店，数据隔离、权限收敛、服务端为事实源。

本次先做两件事：**Phase 1 止血（已执行）**，再进入 **Phase 2 多租户核心闭环**。

## 一、总体目标

| 阶段 | 目标 | 完成标志 | 状态 |
| --- | --- | --- | --- |
| Phase 1 | 止血与定位：可复现、可检查、不误导、最小房间闭环 | lockfile、门禁、0 高危、房间状态机、预览标识 | ✅ 2026-10-31 |
| Phase 2 | 多租户核心闭环：门店上下文 + 房间 + POS + 服务端 | 开房→点单→结账→清台 E2E；跨店越权被拒 | 🟡 进行中（约 70%；真实 API + PostgreSQL/RLS + 认证 RLS/限流 + CSRF/会话刷新已落地，POS/支付未完成） |
| Phase 3 | 模块补齐：报表/会员/库存/员工/设置 | 各模块 P0 用例通过 | ⬜ |
| Phase 4 | 生产就绪：认证、安全、测试、可观测性 | 发布门禁全绿 | ⬜ |

### Task 2.0 门店上下文与租户模型 🟡

- **目标**：引入 `tenantId` + `storeId`；登录后确定当前门店；所有请求自动带门店作用域。
- **已完成（前端占位）**：
  - [x] `Session` 包含 user/tenant/stores/currentStoreId
  - [x] 门店切换仅限授权列表，未授权直接拒绝
  - [x] 前端不信任 URL/表单 storeId；房间查询按门店过滤
  - [x] 写操作校验 `activeStoreId === room.storeId`
  - [x] 侧栏门店切换器 + 会话错误重试
- **已完成（真实服务端）**：
  - [x] 登录：scrypt 校验 + 服务端会话 + HMAC HttpOnly Cookie
  - [x] 登出撤销服务端会话
  - [x] 服务端 403 门店授权校验
  - [x] PostgreSQL RLS：`room/room_order/room_event` 按 `tenantId + storeId` 强制隔离
  - [x] 认证表 RLS：`tenant/store/session` FORCE；`app_user/user_store` 仅经 definer 登录函数读取
  - [x] 登录限流：IP + 账号双维度，超限 429 + `Retry-After`
  - [x] CSRF 同步令牌：写操作校验 `X-CSRF-Token`，缺失/伪造 403
  - [x] 会话刷新：滑动续期 + `SESSION_MAX_LIFETIME_SECONDS` 绝对上限
- **未完成**：
  - [ ] 登录审计 / 会话审计 / 强制下线
- **证据**：`lib/stores/useStoreContextStore.ts`、`server/app.ts`、`db/migrations/001_init.sql`、`db/migrations/002_auth_rls.sql`、`db/migrations/003_session_csrf.sql`、`components/layout/store-switcher.tsx`
