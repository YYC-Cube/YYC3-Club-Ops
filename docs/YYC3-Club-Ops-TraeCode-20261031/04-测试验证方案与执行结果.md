### 1.2 失败判定规则

- **阻断（Blocker）**：任一 P0 用例失败；出现资金/订单不一致；未认证可访问管理端；critical/high 漏洞未处置；构建失败。
- **严重（Critical）**：P1 用例失败 >10%；核心页面出现 console error；核心操作无反馈。
- **一般（Major）**：P2 用例失败；文案/状态/导航不一致。
- **轻微（Minor）**：P3 用例失败；样式与品牌细节。
- 发布门禁：**P0 100% 通过 + P1 ≥90% 通过 + 无 Blocker/Critical** 才允许标记“生产可用”。

## 3. 边界条件与异常场景清单

### 3.1 数据边界

- 空数据：0 包厢、0 商品、0 订单、0 会员、0 员工。
- 超长：包厢名 50 字、商品名 100 字、备注 500 字、会员姓名含 emoji。
- 数值：金额 0 / 0.01 / 负数 / 999999.99 / `0.1+0.2` 精度；数量 0 / 1 / 库存上限 / 超大。
- 时间：跨天 23:59→00:00、时区 Asia/Shanghai、夏令时、服务器/客户端时钟偏差。
- 列表：200 包厢、500 商品、10,000 订单的分页/虚拟化/导出。
- 唯一性：手机号重复、会员卡号重复、条码重复、订单号冲突。
- 状态机：available→occupied→cleaning→available 的非法跳转（如 cleaning→occupied 直接）、重复结账、结账后再点单。

### 3.2 异常场景

| 类别 | 场景 | 预期 |
| --- | --- | --- |
| 网络 | 超时、断网、弱网、请求被取消、重复请求 | 明确提示；幂等；不伪造成功 |
| HTTP | 400/401/403/404/409/422/429/500/502/504 | 分类提示；401 跳登录；429 退避；5xx 可重试 |
| 业务 | 库存不足、会员余额不足、包厢已被占用、订单已支付、退款超额、折扣越权 | 阻断并给出可操作提示 |
| 并发 | 双人同时开同一房、双端同时结账、支付回调重复 | 分布式锁/乐观锁/幂等键，保证只成功一次 |
| 输入 | 空白、纯空格、脚本片段 `<script>`、SQL 关键字、超长粘贴、粘贴带格式 | 校验/转义/长度限制 |
| 设备 | 打印机离线、扫码枪无输入、断网后重连、浏览器刷新/后退 | 降级与恢复路径明确 |
| 存储 | localStorage 禁用/配额满 | 不崩溃；提示并降级 |
| 安全 | Token 过期/被篡改、越权访问其他门店、文件上传伪装 | 拒绝并审计 |

### 4.2 接口契约测试（接入后端后）

| 校验点 | 断言 |
| --- | --- |
| 统一响应 | `{ success, data, message?, error? }` 与 `ApiResponse<T>` 一致 |
| 状态码 | 201 创建 / 400 参数 / 401 未认证 / 403 越权 / 404 不存在 / 409 冲突（重复开房）/ 422 校验 / 429 限流 / 5xx 服务 |
| 幂等 | 结账/支付回调携带 `Idempotency-Key`，重复请求返回同一结果 |
| 分页 | `page/pageSize/total` 一致；稳定排序 |
| 金额 | 服务端以“分”或 decimal 字符串返回，禁止浮点 |
| 时间 | ISO 8601 + 时区；服务端为唯一时间源 |
| 认证 | Bearer/Cookie 失效返回 401；跨店访问 403 |
| 审计 | 开房/改价/折扣/退款/结账均有操作人、时间、前后值 |
| 一致性 | 结账事务内同时写订单、库存、积分、房态；任一失败全回滚 |

### 4.3 E2E（Playwright，建议 5 条核心链路）

1. 登录 → 开房 → 点单 → 结账（现金）→ 清台 → 房态 available。
2. 会员到店 → 会员价 → 会员卡支付 → 积分/余额变化。
3. 库存不足 → 阻止下单 → 补货 → 下单成功 → 库存扣减。
4. 权限：收银员访问报表/设置被拒；店长可访问。
5. 断网/接口 500 → 明确错误提示 → 重试成功 → 不产生重复订单。
