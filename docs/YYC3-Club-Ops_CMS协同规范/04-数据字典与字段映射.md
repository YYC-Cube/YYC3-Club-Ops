# 📚 数据字典与字段映射

> **用途**：让两侧开发在写代码前就知道“字段叫什么、单位是什么、谁生成、怎么转换”。
> **原则**：传输层使用**规范字段（canonical）**；两侧各自用适配器映射，不把一方的内部模型直接暴露给另一方。

---

## 1. 通用约定

| 项 | 规范 |
|---|---|
| 命名 | JSON 用 `camelCase`；数据库用 `snake_case` |
| 金额 | `*Cents`，整数；CMS 的元浮点只在展示层 |
| 时间 | ISO 8601 带 `+08:00`；数据库 `timestamptz` |
| 布尔 | `true/false`，不使用 `0/1` 传输 |
| 空值 | 必填字段不允许 `null`；可选字段省略或 `null` |
| 枚举 | 小写下划线；新增值需契约版本 |
| ID | 字符串，≤64；不使用自增 |
| 图片 | URL 数组；不传二进制 |
| 删除 | `deleted=true` + `deletedAt`；不物理删除主数据 |

### 1.1 字段 owner 与同步方向

> **App 是门店级数据第一写入方**；CMS 只对中央配置可写。字段级归属如下，未列出的字段默认 `S`（App 写）。

| 实体 | CMS 可写字段（C） | App 可写字段（S/T） | 方向 |
|---|---|---|---|
| tenant/store 开通 | tenantId、storeId、code、status、timezone、currency | 门店地址/电话/营业时间 | C: CMS→App；S: App→CMS |
| 商品 | `globalTemplateId`、全局分类/口味模板 | 名称、别名、条码、价格、会员价、库存、成本、上下架、沽清、图片、口味 | S: App→CMS |
| 房型/房间 | `roomTypeTemplateId`、模板名称/计费模板 | 房号、区域、楼层、容量、门店售价、营业状态 | S: App→CMS |
| 计费/套餐 | 模板 ID、模板基准价 | 门店计时/包断/低消/套餐价 | S: App→CMS |
| 门店设置 | 中央默认值、受控开关白名单 | 门店实际开关值 | S: App→CMS |
| 员工 | `userId`、登录手机号、密码、账号状态 | 门店组别、职务、权限、管辖、额度、排班 | C: CMS→App；S: App→CMS |
| 会员 | `memberId` 全局唯一、中央黑名单 | 卡号、等级、余额、积分、充值规则、资料 | S: App→CMS |
| 艺人 | `artistId` 全局唯一、中央模板 | 档案、组别、等级、台费/台票规则、artist_setting 7 项、状态 | S: App→CMS |
| 仓库/库存 | `warehouseId` 全局唯一、供应商主档 | 库存、调拨、盘点、报损、领用 | S: App→CMS |
| 交易事实 | — | 房态、订单、账单、支付、交接、寄存、审批、任务 | T: App→CMS |
| 报表/指标 | 全部（投影） | — | R: CMS→App（查询） |

### 1.2 记录元数据（运营数据必带）

| 字段 | 类型 | 说明 |
|---|---|---|
| `writer` | `app`/`cms` | 本次变更写入方；运营数据必须为 `app` |
| `recordVersion` | int | 单条记录单调递增；CMS 用于顺序/幂等 |
| `changedFields` | string[] | 本次变化字段；CMS 只更新这些字段 |
| `fieldOwners` | object | 可选；字段→`cms/app`，用于冲突校验 |
| `operation` | create/update/delete | 运营数据事件必带 |
| `sourceCommandId` | string | 若由纠正命令触发，记录命令 ID |

**规则**：

- App 事件只允许改 `S/T` 字段；CMS 对 `C` 字段可写。
- CMS 对 `S/T` 字段的修改必须走纠正命令；App 应用后回传新 `recordVersion`。
- 未声明 owner 的新字段：门店级默认 `S`，中央级默认 `C`；必须在契约评审时确认。

## 2. 租户 / 门店

> **归属**：租户/门店开通元数据（ID、code、状态、时区）为 C（CMS）；门店地址/电话/营业时间为 S（App，同步 CMS）。

### 2.1 规范结构

| 规范字段 | 类型 | 必填 | 来源 |
|---|---|---|---|
| `tenantId` | string | ✅ | CMS 生成 |
| `tenantName` | string | ✅ | CMS |
| `tenantStatus` | enum `active/suspended` | ✅ | CMS |
| `storeId` | string | ✅ | CMS 生成 |
| `storeCode` | string | ✅ | CMS，租户内唯一 |
| `storeName` | string | ✅ | CMS |
| `timezone` | string | ✅ | 默认 `Asia/Shanghai` |
| `currency` | enum `CNY` | ✅ | 默认 `CNY` |
| `status` | enum `active/suspended` | ✅ | CMS |
| `roomCount` | int | 否 | CMS |
| `address` / `phone` | string | 否 | CMS |

### 2.2 映射

| CMS 现状 | 规范 | 处理 |
|---|---|---|
| `Store.id`（如 `store_1`） | `storeId` | 通过 `sync_id_map` 映射为稳定 ID |
| `Store.name/address/phone/businessHours` | 同名/拆分 | `businessHours` 拆 `openTime/closeTime` |
| ❌ 无 `tenant_id` | `tenantId` | CMS 必须先补 tenant 模型 |
| ❌ 无 `code/timezone/currency/status` | 同名 | CMS 补字段，默认值见上 |
| Club-Ops `Store` | 同名 | 已接近规范；`code/timezone/currency/status` 已有 |

## 3. 员工 / 权限

> **归属**：账号身份（`userId`/手机号/密码/状态）为 C（CMS）；门店档案（组别/职务/权限/管辖/额度）为 S（App）。App 编辑门店档案后同步 CMS。

| 规范字段 | 类型 | 说明 | CMS 字段 | Club-Ops 字段 |
|---|---|---|---|---|
| `userId` | string | 稳定 ID | `User.id` | `User.id` |
| `tenantId` | string | 租户 | ❌ 需补 | `User.tenantId` |
| `storeIds` | string[] | 授权门店 | `User.storeId`（单值） | `User.storeIds` |
| `name` | string | 姓名 | `name` | `name` |
| `phone` | string | 登录号（PII） | `phone` | `phone` |
| `role` | enum | admin/manager/cashier/waiter/warehouse/marketing/artist_supervisor/system | `role` | `role` |
| `permissions` | string[] | 模块/操作权限 | `permissions` | `permissions` |
| `status` | enum | active/suspended | ❌ 需补 | `User.status` |
| `employeeNo` | string | 工号 | ❌ 需补 | ❌ 需补 |
| `groupId` | string | 组别 | ❌ 需补 | ❌ 需补 |
| `password` | — | **不同步** | 各自认证 | 各自认证 |

> **单门店 → 多门店**：CMS `User.storeId` 需升级为 `store_ids` 或通过 `user_store` 表；同步层输出 `storeIds` 数组。

## 4. 商品 / 分类 / 口味 / 套餐

> **归属**：门店商品/价格/库存/上下架为 S（**App 第一写入**，同步 CMS）；全局模板/分类模板为 C（CMS）。CMS PC 不得直接改门店商品字段，只能发纠正命令。

| 规范字段 | 类型 | 说明 | CMS | Club-Ops |
|---|---|---|---|---|
| `productId` | string | 稳定 ID | `Product.id` | `Product.id` |
| `storeId` | string | 门店 | `storeId` | `storeId` |
| `name` | string | 跨店名称 | `name` | `name` |
| `alias` | string | 门店销售名 | `alias` | `alias` |
| `barcode` | string[] | 一物多码 | `barcode` | `barcode` |
| `categoryId` | string | 分类 | `categoryId` | `categoryId` |
| `unit` | string | 单位 | `unit` | `unit` |
| `originalPriceCents` | int | 划线价 | `originalPrice`（元）→ ×100 | `originalPrice`（需改分） |
| `priceCents` | int | 优惠价 | `price`（元）→ ×100 | `price`（需改分） |
| `memberPriceCents` | int | 会员价 | `memberPrice`（元）→ ×100 | `memberPrice` |
| `memberPricesCents` | object | 分等级会员价 | `memberPrices`（元） | ❌ 需补 |
| `stock` / `minStock` | int | 库存/预警 | 同 | 同 |
| `costCents` | int | 成本价 | `costPrice`（元） | `costPrice` |
| `images` | string[] | 图片 URL | 同 | 同 |
| `flavors` | string[] | 口味 | 同 | 同 |
| `isGift` / `allowDiscount` / `isSale` / `isRecommend` / `isLowConsumption` | bool | 属性 | 同 | 部分（需补 `isLowConsumption`） |
| `displayOrder` | int | 排序 | 同 | ❌ 需补 |
| `commission` | object | 提成 | 同 | ❌ 需补 |
| `status` | enum | active/inactive | ❌ 需补 | 同（POS 表有） |
| `deleted` | bool | 墓碑 | 需补 | 同步层输出 |

**单位换算**：CMS 元 → 规范分必须**四舍五入到分**，禁止 `parseFloat` 后直接乘 100 产生浮点误差；使用 `Math.round(value * 100)` 并在契约测试中验证。

**套餐**：`packageId/name/items[{productId,qty}]/priceCents/validFrom/validTo/roomTypeIds`。

## 5. 房型 / 房间 / 计费

> **归属**：房型/计费模板为 C（CMS）；门店房间、区域、售价、营业状态为 S（**App 第一写入**，同步 CMS）。

| 规范字段 | 类型 | 说明 | CMS | Club-Ops |
|---|---|---|---|---|
| `roomId` | string | 房间 | `Room.id` | `Room.id` |
| `roomTypeId` | string | 房型 | `Room.type` | `Room.type` |
| `name` | string | 房号 | `Room.name` | `Room.name` |
| `area` | string | 区域 | `Room.area` | ❌ 需补 |
| `floor` | int | 楼层 | ❌ 需补 | `Room.floor` |
| `capacity` | int | 容纳 | ❌ 需补 | `Room.capacity` |
| `priceCents` | int | 基础时价 | ❌ 需从 pricing 域来 | `Room.priceCents` |
| `status` | enum | 主数据状态（启用/停用） | `Room.status`（含营业态） | `Room.status`（营业态） |
| `roomTypeName` | string | 小包/中包/大包/VIP/豪华 | `RoomType` | `RoomType` |

> **关键拆分**：`Room.status` 在 CMS 是主数据状态，在 App 是**实时营业态**。规范化：主数据用 `enabled/disabled`；营业态 `available/occupied/reserved/cleaning/maintenance` 只由 App 产生，不同步回 CMS 主数据（只作为事件回传）。

**计费规范**：

| 规范字段 | 说明 |
|---|---|
| `timeRuleId` | 时段 × 房型规则 |
| `roomTypeId` / `timeRange` | 适用范围 |
| `hourlyPriceCents` / `memberHourlyPriceCents` | 计时价 |
| `minimumSpendCents` / `memberMinimumSpendCents` | 低消 |
| `packagePriceCents` / `memberPackagePriceCents` | 包段价 |
| `rounding` | `per_hour` / `per_15min` |
| `priority` | 包段 > 计时 |
| `effectiveFrom/To` | 生效期 |

## 10. ID 映射表

```sql
CREATE TABLE sync_id_map (
  system         text NOT NULL,        -- cms | club_ops
  entity_type    text NOT NULL,        -- store | user | product | room | member | artist
  canonical_id   text NOT NULL,
  source_id      text NOT NULL,        -- 原系统 ID
  source_system  text NOT NULL,
  created_at     timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (system, entity_type, source_id)
);
```

- 过渡期：`cms:store_1 ↔ str_01H...`、`cms:product_1 ↔ prd_01H...`。
- 映射一旦建立不可变；合并/拆分需新映射 + 迁移记录。
- App 交易表只存 `canonical_id`；CMS 投影表同时存 `source_id` 以便回溯。

## 11. PII 与数据质量

### 11.1 PII 分级

| 级别 | 字段 | 处理 |
|---|---|---|
| L3 高敏 | 身份证号/照片、微信 openid、银行卡/支付流水号 | 加密存储；展示脱敏；不写日志；仅授权角色可见 |
| L2 中敏 | 手机号、地址、生日 | 展示脱敏（手机号中间四位）；导出需审批 |
| L1 一般 | 姓名、艺名、房号、订单号 | 正常展示；日志可记录 |

### 11.2 质量规则

| 规则 | 校验 |
|---|---|
| 手机号 | `^1[3-9]\d{9}$`（中国大陆）；其他地区单独规则 |
| 身份证 | 18 位校验码；或护照规则 |
| 金额 | 非负整数；≤ 99,999,999 分 |
| 枚举 | 白名单；未知值拒绝整批 |
| 时间 | 不早于 2020；不晚于当前 +1 天 |
| 名称 | 1–100 字符；去首尾空格 |
| 条码 | 字符串数组；每项 1–64；去重 |
| 引用 | 外键必须存在；否则整批拒绝 |
| 唯一 | `store + name`（商品/房间）；`tenant + phone`（员工） |
