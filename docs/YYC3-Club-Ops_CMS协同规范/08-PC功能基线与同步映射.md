## 2. 双端职责（结合手册与 App 事实）

| 端 | 定位 | 手册对应 |
|---|---|---|
| **CMS PC** | 桌面管理、批量/导入、打印、报表、设备配置、账单更正、中央模板 | 本手册 7 大模块 |
| **Club-Ops App** | 现场高频操作、门店数据编辑、交易、房态、审批、任务 | App 操作手册 + 本手册中可在现场执行的子集 |
| **边界** | PC 对门店字段的修改走纠正命令；App 应用后回传事件；PC 不直接写 App 事实 | 见 `02` 第 6 章 |

> **重要**：手册中的功能不是全部搬到 App，也不是全部由 PC 直接写。**同一字段只有一个写入方**，PC 的门店级操作通过命令通道落地。

## 3. 模块 → 数据域 / 归属 / 同步映射

图例：C=CMS 中央配置；S=App 门店运营；T=App 交易；R=CMS 报表投影。

### 3.1 销售

| 手册子模块 | 数据域/实体 | 级别 | 第一写入 | 同步/事件 | PC 行为 |
|---|---|---|---|---|---|
| 订单列表 | `room_order`、`order_item` | T | App | `order.*` → CMS | 只读查询/导出；**无命令**（交易事实） |
| 账单列表 | `bill`、`bill_item` | T | App | `order.checkout.completed` | 只读查询/导出；更正走 `bill.correct`（§3.7） |
| 在线预定 | `booking` | T | App | `booking.*` | 只读查询/跟进；**新增一律 App 第一写入，PC 不新增**（`09` §3-7） |

### 3.7 账单

| 手册子模块 | 数据域/实体 | 级别 | 第一写入 | 同步/事件 | PC 行为 → 命令 |
|---|---|---|---|---|---|
| 账单制作 | `bill`、`bill_item` | T | App | `bill.adjusted`（App 应用后） | `bill.correct(operation=update/delete/batch_delete/keep_room_package_only)`；**打印不属于更正** |

## 4. PC 操作 → 同步方式（统一规则）

| PC 操作类型 | 同步方式 |
|---|---|
| 编辑中央配置（租户/门店开通/全局模板/权限模板/报表定义/门店列表） | CMS 直接发布 `centralVersion` → App 只读同步（通道 A） |
| 新增/修改/删除**门店级**数据（商品、价格、会员、员工档案、艺人、设置、仓库主数据/规则） | CMS 生成 `command.record.upsert`（operation=create/update/delete）→ App 应用 → App 回传 `master.*` + `command.applied` |
| 语义为「纠偏」的少量字段修正 | `command.record.correct` 保留**仅用于纠正**（带 reason/审计），不再承担新增/修改（`09` §3-1） |
| 仓库六类单据（采购/退货/调拨/报损/领用/盘点） | CMS 生成 `command.stock.document`（documentType 枚举）→ App 应用 → 回传 `inventory.*.posted` |
| 账单修改/删除/批量删除/只保留开房套餐 | CMS 生成 `command.bill.correct`（operation 枚举 + 审批/限额/快照）→ App 应用 → 回传 `bill.adjusted` |
| 报表查询/导出 | App/CMS 查询 CMS 投影；不反向写 |
| 批量导入商品/员工/影片 | `command.catalog.import` / `command.staff.import` / `command.movie.import`（校验/部分成功/幂等，见 §5.3） |

**禁止**：PC 直接写 App 的 `operational_*` / `room_order` / `bill` 表；PC 直接改 CMS 投影“抹平”差异。

### 5.2 命令（CMS→App）

| 命令 | 用途 | 关键约束 |
|---|---|---|
| `command.record.upsert` | 门店级主数据/规则的新增/修改/删除（operation=create/update/delete） | 替代原 record.correct 的新增/修改语义；含 `copyFrom`（开房套餐复制） |
| `command.record.correct` | **仅纠正**门店字段（纠偏/修复） | 必带 `reason` + 审计；不再承担日常新增/修改 |
| `command.record.archive` | 封存/停用 | 发 `master.*.deleted` |
| `command.catalog.import` | 批量导入商品/分类/口味/套餐 | payload 见 §5.3-1 |
| `command.staff.import` | 员工批量导入 | 模板/校验/错误行同 catalog.import（`09` §3-2） |
| `command.movie.import` | 影片批量导入 | 文件/封面走对象存储引用（`09` §3-3） |
| `command.stock.document` | 六类仓库单据 | `documentType` 枚举 + `docNo` 幂等，见 §5.3-2；**不含仓库/供应商等主数据** |
| `command.bill.correct` | 账单更正（4 类 operation） | 审批/限额/前后快照，见 §5.3-3；**不含打印** |
| `command.settings.update` | 设置变更 | 必带 `domain`（store_settings/deposit_rule/rounding_rule/marquee…）；rounding 另带 `scope` |
| `command.device.update` | 收银机/打印机/打印规则 | 必带 `deviceType`（cashier/printer/print_rule/...） |
| `command.vod.update` | VOD/轮播/包厢参数 | 必带 `domain`（config/rotation/room_param/hall_tv/...） |
| `command.artist_setting.update` | 艺人设置 7 项 | App 写、CMS 投影前提下的 PC 受控写入口 |
| `command.store.suspend` / `command.price.override` | 停业 / 强制价格 | 见 `02` §6.2；override payload `{priceCents}`，审计快照三元组 `overrideCents/overrideReason/overrideOperatorId` 见 `04` §4 |

**命令生命周期**（`09` §3-8，补 `03` 仅 applied/rejected 的缺口）：

```text
issued → delivered → applied | rejected → projected
                └── 超时 → 重试（指数退避）→ dead → 人工介入
```

> 事件/命令字段级定义见 `04`；传输/幂等/顺序见 `03`；命令通道见 `02` 第 6 章。

### 5.3 三个重点命令 payload 定义（评审采纳，`09` §2）

**1）`catalog.import`（商品批量导入）**

```json
{
  "commandType": "catalog.import",
  "commandId": "cmd_01H...",
  "idempotencyKey": "importJobId+fileChecksum",
  "tenantId": "tnt_...", "storeId": "str_...",
  "payload": {
    "importJobId": "imp_01H...",
    "mode": "apply",                  // validate | apply（dryRun=validate）
    "conflictPolicy": "update",       // skip | update | abort
    "fileChecksum": "sha256:...", "fileName": "products.xlsx", "rowCount": 100, "maxRows": 5000,
    "rows": [ { "rowNo": 1, "entity": "product", "operation": "create", "data": { } } ]
  },
  "expectedVersion": 1, "issuedBy": "usr_...", "issuedAt": "2026-11-01T...+08:00"
}
```

- 幂等键：`importJobId + rowNo + checksum`；同文件重复导入 **0 重复建品**。
- 逐行结果：`errors[]{rowNo, entity, code, message}` + 汇总（success/skip/fail）；**部分成功必须明确**。
- PC 前置：导入前先本地校验模板；回传事件带 `sourceCommandId` + `importJobId`。
- 验收：100 行模板成功/跳过/错误行可下载；重复导入 0 重复；失败可重试。

**2）`stock.document`（六类仓库单据）**

```json
{
  "commandType": "stock.document",
  "commandId": "cmd_01H...",
  "idempotencyKey": "docNo",
  "tenantId": "tnt_...", "storeId": "str_...",
  "payload": {
    "documentType": "purchase",       // purchase | purchase_return | transfer | damage | requisition | count
    "docNo": "PO-20261101-001",
    "warehouseId": "wh_...", "fromWarehouseId": null, "toWarehouseId": null,
    "supplierId": "sup_...", "reason": "", "approvalId": null,
    "items": [ { "skuId": "sku_...", "qty": 24, "unitCostCents": 800, "batchNo": "B-1", "expiry": "2027-01-01" } ]
  },
  "expectedVersion": 1, "issuedBy": "usr_...", "issuedAt": "2026-11-01T...+08:00"
}
```

- `documentType` → 事件映射与校验：

| documentType | 事件 | 关键校验 |
|---|---|---|
| `purchase` | `inventory.purchase.posted` | 供应商、单价、入库仓 |
| `purchase_return` | `inventory.purchase_return.posted` | 原采购单；退货 ≤ 入库数量 |
| `transfer` | `inventory.transfer.posted` | 出/入仓不同；同店跨仓/跨店策略 |
| `damage` | `inventory.damage.posted` | 报损原因 + 审批 |
| `requisition` | `inventory.requisition.posted` | 领用人、用途 |
| `count` | `inventory.count.posted` | 系统库存 vs 实盘；盘盈亏原因 |

- 幂等：`docNo` 门店内唯一；重复提交不得重复扣减库存；事件带 `sourceCommandId`/`documentType`/`docNo`。
- 审批：盘点/报损/调拨需审批或限额（`approvalId`）。

**3）`bill.correct`（账单更正）**

```json
{
  "commandType": "bill.correct",
  "commandId": "cmd_01H...",
  "idempotencyKey": "billId+operation+expectedVersion",
  "tenantId": "tnt_...", "storeId": "str_...",
  "payload": {
    "operation": "batch_delete",      // update | delete | batch_delete | keep_room_package_only
    "billIds": ["bill_...", "bill_..."],
    "reason": "收银误操作",
    "approvalId": "appr_...", "operatorId": "usr_...",
    "beforeSnapshot": { },
    "limits": { "maxBills": 20, "maxAmountCents": 500000 }
  },
  "expectedVersion": 3, "issuedAt": "2026-11-01T...+08:00"
}
```

- 高危控制：审批 + 金额阈值 + 双人复核 + 原因 + **修改前后快照**；批量删除限条数/金额并逐条审计。
- `keep_room_package_only`：定义删除哪些明细、是否保留房费/套餐、是否影响已支付/挂账。
- 并发：`billId + expectedVersion`；冲突返回 `version_conflict`；打印动作移出本命令。
- 事件：`bill.adjusted` 携带 `sourceCommandId` + 修改前后摘要；验收含 4 类 operation 用例 + 金额勾稽 + 审计可查。
